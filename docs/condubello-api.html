Condubello API

API REST que gestiona una escuela de conducción: estudiantes, instructores, vehículos, sesiones prácticas, telemetría GPS de cada prueba, validaciones antifraude con foto y el control de horas que exige cada categoría de licencia.

Arquitectura

Arquitectura limpia en cuatro proyectos. Las dependencias apuntan hacia el dominio: el dominio no conoce a nadie, y la API conecta todo al arrancar.

ApiCondubello.Api

Controladores delgados: reciben la petición, la envían por MediatR y traducen el Result<T> a un código HTTP con HandleResult. Aquí están la configuración JWT, Swagger, el middleware de excepciones y CurrentUser, que lee el usuario del token.

Los casos de uso. Cada carpeta de Features/ tiene sus Commands (escriben), Queries (leen), DTOs y validadores. También contiene los handlers genéricos (GetAllHandler, GetByIdHandler, DeleteHandler), el tipo Result<T> y el AuthorizationBehavior que aplica los permisos por rol.

EF Core sobre PostgreSQL con nombres en snake_case, la configuración de cada tabla, un repositorio genérico Repository<T>, la unidad de trabajo, el generador de tokens JWT, el hash BCrypt y el seeder del primer administrativo.

Entidades, enums (Rol, EstadoPrueba, EstadoVehiculo) y las interfaces IRepository<T> e IUnitOfWork.

Recorrido de una petición

Ejemplo: un instructor marca una sesión como completada con PATCH /api/sesiones-practicas/{id}/seguimiento.

  1. AutenticaciónEl middleware JWT valida firma, emisor, audiencia y vigencia del token (8 horas). Sin token válido responde 401.
  2. ControladorSesionesPracticasController solo exige que haya sesión iniciada. ASP.NET valida las anotaciones del DTO (por ejemplo, calificación entre 1 y 5) y, si fallan, responde 400 con la lista de errores por campo.
  3. MediatREl controlador envía ActualizarSeguimientoSesionCommand con Sender.Send(...).
  4. Autorización por rolAuthorizationBehavior lee el atributo [Autorizar(Administrativo, Instructor)] del command. Si el rol del token no está en la lista, devuelve 403 sin ejecutar el handler.
  5. HandlerCarga la sesión. Si el usuario es instructor y la sesión no es suya, devuelve 403. Después valida con SesionPracticaValidator (cruces de horario, fin posterior al inicio, una sesión COMPLETADA necesita fecha de fin) y recalcula la duración.
  6. PersistenciaEl repositorio marca la entidad como modificada y IUnitOfWork.SaveChangesAsync la guarda en PostgreSQL.
  7. RespuestaEl handler devuelve Result<SesionPracticaDto> con advertencias (por ejemplo, “la sesión dura más de 2 horas”). HandleResult lo envuelve en ApiResponse y responde 200.

Todos bajo /api. Salvo el login, todos piden token: Authorization: Bearer <token>. Los recursos de sesiones, telemetría, validaciones, control de horas, vehículos, instructores y administrativos siguen el mismo patrón CRUD.

Reglas de negocio

Personas

  • La cédula es única dentro de cada tipo de persona y solo admite números (5 a 20 dígitos).
  • El email es único entre estudiantes, instructores y administrativos, porque el login es común. Se guarda en minúsculas.
  • No se puede eliminar un estudiante ni un instructor con sesiones registradas, ni el único administrativo del sistema.

Sesiones prácticas

  • La fecha de fin debe ser posterior a la de inicio, y una sesión COMPLETADA debe tener fecha de fin.
  • Ni el instructor ni el estudiante pueden tener dos sesiones cruzadas en el horario (las canceladas no cuentan; si no hay fin se asume 1 hora).
  • La duración se calcula a partir de las fechas. Si pasa de 2 horas, se devuelve una advertencia.
  • Hay advertencias si la sesión queda en FRAUDE_DETECTADO, si el estudiante no tiene control de horas o si ya completó sus horas.

Licencias, telemetría y vehículos

  • Categorías de licencia válidas: A1, A2, B1, B2, B3, C1, C2 y C3. Las horas requeridas van de 1 a 500.
  • La ruta GPS debe ser GeoJSON válido (Point, LineString, FeatureCollection, etc.).
  • No se registran validaciones antifraude en sesiones CANCELADAS; una validación fallida sugiere marcar la sesión como fraude.
  • Placa con formato ABC123 (carro) o ABC12D (moto), única. Cambiar o borrar un vehículo EN_CLASE genera una advertencia.

Estado actual

Listo

Los cuatro proyectos compilan sin errores ni advertencias. El CRUD de las ocho entidades, el login con JWT y los permisos por rol están implementados.

Sin probar

Los permisos no se han probado contra la base de datos: al arrancar, PostgreSQL rechazó la contraseña del usuario postgres configurada en appsettings.json.

Pendiente

No hay pruebas automatizadas ni migraciones de EF Core en el repositorio; la API supone que las tablas ya existen.

Pendiente

Las horas realizadas del control de horas no se suman solas al completar una sesión; hay que actualizarlas a mano.

Por decidir

Con los permisos actuales, el estudiante no puede calificar a su instructor (CalificacionAlumnoAInstructor); solo el administrativo puede escribir ese campo.

Por decidir

La API no compara la foto antifraude ni calcula la alerta de desviación de ruta: quien llama envía EstadoValidacion y AlertaDesviacion ya resueltos.
